# Decisions taken while building the redaction foundation

Thirty rulings made during implementation of
`docs/superpowers/plans/2026-08-23-redaction-foundation.md`. Each records what was
decided, why, and what it costs if the decision is wrong.

These were judgement calls made on the author's behalf. Read them before changing
the redaction layers: several encode a tradeoff that is not obvious from the code,
and a few reverse an earlier decision in the same list.

The working ledger, task reports, and review transcripts live in
`.superpowers/sdd/2026-08-23-redaction-foundation/`, which is git-ignored scratch.

---

## 1. AGENTS.md lines 5-7 and 17 left stale. The plan's Step 7 named only the "Key files" bullet, but the spec's "Package rules that must change" table requires AGENTS.md to describe the grader, the Humanizer component, and the shared reference. Spec is binding, so both findings are in scope and get fixed. Cost if wrong: a few lines of repo documentation rewritten more thoroughly than the plan asked.

## 2. the reviewer's Critical (":02d breaks at the 100th token") is REJECTED. It conflicts with the plan text, which is mine to rule on. `:02d` is a minimum field width, not a fixed width, and the downstream token regex is `\d{2,}` (two OR MORE digits), so three-digit tokens are accepted by construction. Verified empirically: 101 allocations give STUDENT_99 -> STUDENT_100 -> STUDENT_101, all unique, all matching the regex, none matching inside another under \b. tokens.py is unchanged. Cost if wrong: if some later consumer really did require exactly two digits, batches over 99 of one kind would mis-tokenize — but no such consumer exists in tasks 5-12, and I checked each one.

## 3. restructure redact_roster into two passes (all full names/emails/IDs first, bare names only after), and key bare tokens on the LITERAL bare form rather than the student's full name. Why: pass ordering is what causes the misattribution, and literal-keyed tokens are what make rehydration exact. One brief test assertion changes (bare "Maya" now yields STUDENT_02, not STUDENT_01) — I traced all nine existing tests and only that one shifts. Cost if wrong: the map holds one extra token per distinct bare form used, and the model sees two tokens for one person, which does not matter because the grader never reasons about identity.

## 4. move the protected-name shield to run BETWEEN pass 1 and pass 2, not first. Precedence is deliberate — a student's full name is PII and must be tokenized even when it contains the instructor's name; the shield's real job is protecting remaining instructor mentions from the bare-name pass. Cost if wrong: an instructor mention that is textually identical to a student's full name would be tokenized; that case is pathological and the roster-coverage check would surface it.

## 5. record one BareHit per occurrence via re.finditer, not one per variant. Cost if wrong: a longer review file on essays that repeat a name many times.

## 6. replace the length sort in full_name_variants with explicit precedence — natural "First Last", then "Last, First", then "F. Last". Cause was that the comma form is LONGER (14 vs 13 chars) so the -len sort tried it first and it matched greedily across the comma boundary. My own ruling R2 made that ordering deterministic without making it correct; this supersedes R2 for full names only. bare_name_variants keeps the (-len, s) sort, which is correct there. Verified the fix resolves all three cases including the existing "Lin, Maya" test. Cost if wrong: a roster-listing-style "Last, First" mention that appears BEFORE any natural-form mention in the same file would still be caught, just second in precedence — no case is lost.

## 7. replace DEFAULT_ID with a CUE-GATED pattern requiring a student-ID cue word and capturing the identifier in group 1. Why: one change fixes both the Critical false hits (patent/case numbers) and the Important misses (all-digit, lowercase, hyphenated IDs), because the cue word is what disambiguates an identifier from a citation. Verified against 11 cases, all correct. Deliberate consequence: a bare "S1000431" with no cue is no longer caught by layer 2 — acceptable because layer 1 catches every roster ID by exact match. Cost if wrong: a non-roster person's bare ID written without any cue word would survive layer 2; layer 4 review flags remain the backstop.

## 8. PROFILE_URL org-vs-personal ambiguity is DEFERRED, not fixed. No regex can distinguish a student's profile from a cited organisation's. Identity protection wins by default (consistent with the bare-name precedent), and the correct remedy is surfacing URL substitutions in the pipeline's LOCAL review file so the instructor can spot a wrongly-redacted citation. Carry into Task 10 and document in Task 12's references/redaction.md. Cost if wrong: a legitimately cited organisational account is tokenized, which the instructor sees in the review file and can restore.

## 9. widen the cue gate to tolerate up to 6 characters of markdown/punctuation between cue and identifier, and add "SID" and "Student Number" as cues. Why: the corpus headers use markdown bold (`**Student**: `), so "**Student ID**: X9998887" is a realistic form. Verified against 15 cases and a 20k-cue backtracking check (0.007s). The pattern now has TWO capture groups, so substitution must read group(1) or group(2). Cost if wrong: a 6-character filler window could let a cue word bind to a nearby unrelated number; I tested the realistic false-positive set and none matched.

## 10. tighten PHONE to (?<![\w.])...(?!\w) and anchor PROFILE_URL with (?<![\w/.]). Why: my own digit-only lookarounds mangled "v1.415.555.0142" and "https://archive.org/x.com/y". Both are Minor (low realism) but the fix is free.

## 11. this SUPERSEDES my earlier "URL org-vs-personal is undecidable, defer" ruling. Two discriminators do decide most of it: reserved platform paths (rules, tos, terms, privacy, ...) are never profiles, and a github URL with a second path segment is a repository. linkedin keeps a bare match because /in/ is itself a profile marker. Verified 16 cases: 7 profiles still redacted, 9 citations survive. Cost if wrong: a student whose handle happens to equal a reserved word (e.g. github.com/docs) is missed; layer 1 still catches their name, and the review file remains the backstop.

## 12. require an explicit STUDENT cue ("student", "student id", "student number", "sid"); drop bare "id" as a cue. Why: "id" plus a number is not evidence of a person, and layer 1 already catches every roster student's ID in any format. Verified 18 cases (7 hit, 11 miss) and verified end-to-end that layer 1 still catches the Task 12 leak-test seeds "ID S1000432" and "Student S1000433". Deliberate cost: a NON-roster person's ID written as "ID#: X9998887" is now missed. Accepted — a rare miss in exchange for removing a realistic gradeability bug, consistent with the spec's stated tradeoff. One test I added in round 3 (test_an_id_hash_colon_header_is_caught) becomes wrong by design and is replaced.

## 13. use a POSSESSIVE quantifier for the github handle — `[\w.-]++(?!/[\w.-])` (Python 3.11+; repo runs 3.13). Why: possessive matching refuses to give characters back, which simultaneously removes the backtracking hole that made the simpler `(?!/)` forms unusable AND eliminates the quadratic rescan. Verified 15 cases plus timing: N=32000 drops from 1.32s to 0.0001s, and the trailing-slash profile now redacts while repos still survive. Cost if wrong: possessive quantifiers are a newer regex feature; on a pre-3.11 interpreter this would be a syntax error. The repo already requires 3.13 elsewhere, so acceptable.

## 14. EXCEED the 5-round cap for one focused round 6. Why: the cap exists to detect an implementer that cannot converge. This implementer closed every round it actually received; the failure is that my addenda keep racing its commits — a delivery problem on my side, not a convergence problem. Adjudicating away a fix that was never attempted would be the wrong call. Cost if wrong: one extra round on a task that has already had five. Mitigation: round 6 requests an explicit receipt handshake before work starts.

## 15. the test gets a real behavioural assertion plus a loose timing backstop. Verified the two patterns differ in RESULT, not just speed — the old lookahead returns NO match on "github.com/" + "a"*20000 + "/" while the possessive form returns count 1. So `assert count == 1` binds with no clock dependency; the 0.5s budget (2500x current, ~half the quadratic time) is a backstop against a reintroduced quadratic form that still matches. Cost if wrong: a timing assertion could in principle flake on an extremely loaded machine; the behavioural assertions would still hold.

## 16. allow a possessive in the cue (straight and curly apostrophe), AND add a cue-independent sweep that replaces later bare repeats of any ID value already established by a CUED match. Why the sweep is safe: a value only enters the sweep set because a cued match already proved it is a student ID, so nothing uncued is ever swept. Verified both directions — the repeat leak closes while "Docket ID 12345678" is preserved. Cost if wrong: if a cued match ever fired on a non-person number, the sweep would propagate that error through the document; the cue's false-positive set is the thing holding that back, and I tested it against Docket/Case/Patent/bare-id.

## 17. REVERSED my own inclination to add a cp1252 fallback for text files. The reviewer argued refusing is correct because cp1252 decodes ANY byte sequence, so a fallback always "succeeds" and would silently mask a different encoding with mojibake — and mangled names break roster matching, which turns a gradeability wart into a leak. Keeping the refusal; fixing only the error message to be actionable. Cost if wrong: an instructor with cp1252 files must re-save them as UTF-8 before grading.

## 18. extract table cells into the BODY (they are essay content, joined " | " per row) but route headers, footers and all core_properties into a new `metadata: tuple[str, ...]` channel, replacing the single `author: str`. Why: header and footer text is not essay content and must not be graded, but it can carry a name that must be tokenizable. Add `empty_body: bool` so a blank submission is REPORTED rather than silently graded — not an error, because a blank submission is a real event the instructor must see. Cost if wrong: Task 10 must consume `metadata` and `empty_body` instead of `author`; Task 10 is unwritten so nothing breaks today.

## 19. replace the docx body extraction with document-order iteration over doc.element.body, deduping merged cells by id(cell._tc) and recursing into nested tables. Why: three separate defects (merge duplication, scrambled reading order, lost nested content) all stem from the same shortcut of reading doc.paragraphs and doc.tables as two flat lists. One correct traversal fixes all three. Verified all four shapes: nested -> 'OUTER IN-a | IN-b'; merged -> 'A B\nC | D'; order -> table sits between its paragraphs; empty cell -> 'X |  | Z' keeping column position. Cost if wrong: the traversal touches python-docx internals (cell._tc, CT_P, CT_Tbl) which are not a documented public API and could shift in a future python-docx release; the tests pin the behaviour so a break would surface loudly rather than silently.

## 20. dedupe metadata order-preservingly and drop the python-docx default strings. Cost if wrong: a student whose name genuinely is "python-docx" is not a case worth designing for.

## 21. rework layer 4 — widen RELATION (add landlord/teacher/classmate/colleague/ supervisor) and allow an apposition comma; add a CONTACT verb pattern (spoke with / talked to / interviewed / met with); add a possessive pattern gated on the sentence containing first-person markers; restrict SPEECH to "me" not "us"; drop Senator and Rep. from TITLE; scope the citation skip to the SENTENCE rather than the document; report every occurrence but dedupe within a sentence; and accept a `protected` argument so the instructor is skipped. Verified: all 6 miss cases now caught, all 7 false-flag cases clean, Brady no longer suppressed, both Daniel occurrences reported, and corpus false positives drop from 7 to ZERO. Cost if wrong: the possessive pattern is the loosest addition — it fires only when the sentence also carries first-person markers, but an essay written in the first person about a scholar ("I find Habermas's argument weak") would flag "Habermas". That is one line for the instructor to dismiss, against catching a named interview subject.

## 22. split RELATION into REL_MY and REL_OUR. "my partner" is a person; "our partner" is usually a company. The narrower "our" list drops partner, boss and coworker. Cost if wrong: "our coworker Elena" is missed; "my coworker Elena" still fires.

## 23. a test that passes because no pattern fires is decoration, not coverage. The replacement citation test must put a cited name in a context that DOES fire a pattern ("Professor Gillespie (2014) argues...") so only the skip can suppress it, and the round requires a mutation check proving it fails without the skip. Verified both directions plus the sentence-scoping companion test.

## 24. add DOCUMENT-level citation suppression, but ONLY for the WEAK patterns (possessive and quote-attribution). A name appearing anywhere as "Name (Year)" is a scholar throughout the document. The STRONG patterns (relation word, title, "told me") keep SENTENCE scoping, so the Brady bug cannot return — that bug was harmful precisely because it suppressed strong signals. Verified on a mixed essay: Gillespie and Habermas suppressed for weak patterns, Elena (never cited) survives, an uncited "Brady's" also survives. Cost if wrong: a private individual who happens to share a surname with a scholar cited in the same essay loses their weak-pattern flag; their strong-pattern flags still fire.

## 25. a YEAR must never be sufficient on its own — it may only enrich a warning raised by a STRONG marker. Add status, health, military and firstgen to the strong set alongside family, employer and hometown. Verified all 14 cases: every false positive gone, all eight true positives caught including the five that were missing. Cost if wrong: a bare dated personal event with no other marker ("in 1998 everything changed for me") is missed. That is a narrower loss than a layer the instructor stops reading.

## 26. refuse to write into a non-empty destination (new exit code 5), with an explicit --force that first deletes prior token-named outputs but leaves unrelated files alone. Why: the fail-closed design actively encourages re-running after fixing a warning, which is exactly when stale files get graded. A refusal is consistent with the no-silent-partial-success rule, and clearing only token-shaped names avoids destroying anything the instructor put there deliberately. Cost if wrong: an instructor who genuinely wants to accumulate output across runs must pass --force each time.

## 27. attribute by EARLIEST POSITION IN THE RAW TEXT rather than allocation order — the author is named in the header, a classmate is cited in the body. Verified CSV-order-independent (Zoe both ways) and correct on all five real papers. ALSO report an `ambiguous_authorship` entry whenever a file names more than one roster student: position is a good heuristic, not a guarantee, and the instructor must see the cases where it had to choose. Not an error, no exit-code change — citing a classmate is legitimate. Cost if wrong: a paper that cites a classmate BEFORE naming its own author is misattributed, and the review file is the only thing that surfaces it.

## 28. after TWO dispatched implementers failed to start and neither answered a handshake, I implemented Task 12 in the controller session. The "never fix things yourself" rule exists to protect context hygiene and review coverage; here the delegation channel itself was failing, and leaving the final task undone was worse. Review coverage is preserved by dispatching an independent review of the result. Cost if wrong: my own context carries the implementation detail for this one task.

## 29. clear the last deferred Important rather than hand it over unresolved. The "M. Smith" collision gets a token keyed on the LITERAL ambiguous form — the same device that fixed bare names in layer 1. Verified: no plaintext leak, no misattribution, round trip character-identical. Rejected alternatives: skipping the form leaves "M. Smith" in the output; binding it to one student IS the misattribution. Dispatched to impl-task-12b rather than done in-session, so the delegation and review path stays intact now that agents are responsive again.

## 30. key EVERY initial form on its literal, ambiguous or not. This makes the code SIMPLER — the ambiguity Counter can be deleted, because both cases collapse to one path — and makes the round trip exact in both. Verified: two-Smiths restores exactly with 3 tokens; M. Lin restores exactly with 2. Nothing depends on the initial form binding to a student, since authorship attribution uses earliest FULL-name position. Cost if wrong: one extra token per distinct initial form actually used in a document.
